Chapter 02 / Negative sampling intuition

Learn word representations by distinguishing data from noise

Build the training task first. Then follow one pair through its score, output, loss, and weight changes before watching the full run.

This page explains why the operations exist. The math & code walkthrough expands their calculations. Full-softmax Word2Vec uses a different prediction task; negative sampling is not that same probability distribution calculated faster.

1. Build a task that gives word vectors useful feedback

We want a small list of learned numbers for each word: its embedding. A word ID identifies a word, but numerical distances between arbitrary IDs say nothing about its usage. Adjustable coordinates can reflect usage, provided we give them a task connected to text.

cats furry petsdogs furry petscats playful pets

With a window of one, the first sentence yields cats / furry, furry / cats, furry / pets, and pets / furry. Each is a center word paired with an observed neighbour. We can use these pairs as training evidence without being told the correct embedding coordinates.

Full softmax learns by predicting an observed context among all vocabulary words. Negative sampling changes that job: distinguish an observed pair from a pair constructed using a sampled noise word. Each update needs only a few candidate scores instead of every vocabulary score.

The labels come from how we obtained an example

Give an observed pair such as cats / furry label 1. Draw three words from a sampling distribution and pair each with the same center; give those pairs label 0. If cars is drawn, cats / cars is a label-0 example.

Label 0 does not mean “known to be unrelated.” Playful can be sampled as noise even though cats occurs beside playful elsewhere in the text. The current observed context is rejected by the sampler, but other neighbours, the center word itself, and repeated samples are allowed.

Both kinds of example are necessary for this task. If we trained only on label 1, giving every pair a high score would reduce loss without learning useful distinctions. Noise examples make that shortcut costly. Cats and dogs still receive related feedback because they share observed contexts, but now that signal competes with sampled noise.

Sampling rule, actual sentences, and run settings

The sampler assigns weight count^0.75 to each word, then normalizes these weights to probabilities. Frequent words are useful, plausible alternatives, but the exponent reduces their dominance: pets occurs 9 times and cats 3 times, giving weights about 5.196 and 2.280 rather than 9 and 3. Sampling is not a search for words the model has proved wrong.

The chapter's 27 sentences, 21 words, 108 directed pairs, window 1, D = 3, K = 3, and NumPy-compatible seed 42. The default learning rate is 0.05. This page extends training to 200 epochs; the script defaults to 50. Controls replay measured checkpoints.


    

  


  

    
2. Turn one pair into a binary prediction

    

      
The model stores two tables of adjustable numbers, or weights. E holds a vector for each word as an input. W holds a vector for each word as a candidate context. Each vector has three coordinates here, initially random.

      
The forward calculation receives the center word and candidate word. It does not receive their label. We use the label only afterward to decide whether its output was helpful.

      
Providing the candidate does not give away the answer in this task: the unknown is whether this pair was observed or sampled. In full softmax, the unknown was which context word occurred. Changing the question changes what information belongs in the input.

    

    

    
The selected example comes from the observed pairs. Below, we also examine the feedback a noise label would demand. All worked values follow the epoch selected in the training section.

    
Look up one vector for each role

    

    
The two tables let a word have different adjustable values for the input and context roles. When furry is a candidate, the calculation uses its vector in W, not E[furry]. This implementation learns compatibility between the roles rather than directly comparing two input embeddings.

    
Combine the vectors into a score

    
We need the output to depend on both participating vectors so feedback can change both. A dot product does that: multiply each input coordinate by the corresponding candidate coordinate and add the products.

CoordinateInput valueCandidate valueProduct
Add the three products: score

    

    
The score is an unrestricted compatibility number. Positive and negative coordinate products can reinforce or cancel. A large score is not itself a probability or a guarantee that the words mean similar things.

    
Use sigmoid to express the score as a binary output

    
The training label has two possible values. We want an output between 0 and 1 that can be compared with those labels. Sigmoid maps the score onto that range smoothly: score 0 maps to 0.5, increasingly positive scores approach 1, and increasingly negative scores approach 0.

    
q = 1 / (1 + exp(-score))

    
Here exp(s) means e raised to s, with e approximately 2.718. At score 0, exp(0) = 1, so the denominator is 2 and q = 0.5. A positive score makes exp(-score) smaller, reducing the denominator and raising q.

    
The output q is the model's data-versus-noise prediction for this pair. The remaining 1 - q is assigned to label 0. For example, q = 0.9 assigns 90% to label 1 and 10% to label 0.

    
Another way to see this choice of mapping is through odds: compare the two assigned probabilities as a ratio. At q = 0.9, the data-to-noise odds are 0.9 / 0.1, or 9 to 1. Sigmoid makes those odds equal exp(score). Score 0 gives odds 1 to 1; raising the score increasingly favours label 1. This is a chosen model of the label probabilities, not a measurement of whether a word is truly related.

    
A hard yes/no threshold would throw away the distinction between a barely positive score and a strongly positive one. The smooth sigmoid retains that changing preference, so the loss can give feedback even when a small score change would not flip a yes/no decision.

    

    
We did not use any other word's score to obtain q. Each pair has a separate binary output, so outputs across the vocabulary do not sum to 1. They are not next-word probabilities or a calibrated list of true neighbours.

  


  

    
3. Use the label to decide which output is helpful

    

      
Now reveal how the example was obtained. The output always means the same thing: a high q favours the data label. But whether that is helpful depends on the example's actual label.

These examples need feedback in opposite directions. A low output is a mistake for an observed example; a high output is a mistake for a noise example. We call the numerical cost of a prediction its loss. A costly prediction should become cheaper as it agrees more with the label.

      
Choose the probability assigned to the actual label

      
The model assigns q to label 1 and 1 - q to label 0. For an observed example, use q. For a noise example, use 1 - q. Binary cross-entropy applies -log to that selected probability: high probability for the actual label gives low cost.

      
Log reverses exponentiation: log(0.5) is about -0.693 because e raised to -0.693 is about 0.5. Probabilities below 1 need negative powers, so the minus sign makes the cost positive. Larger assigned probability gives a smaller cost.

The logarithm connects individual costs to fitting the labels

      
Suppose one observed example receives q = 0.8 and one noise example receives q = 0.3. The model assigns their actual labels probabilities 0.8 and 0.7. Under the per-example likelihood model, their combined probability is 0.8 × 0.7 = 0.56.

      
Maximizing such products is equivalent to minimizing a sum of negative logarithms. Here -log(0.8) - log(0.7) = -log(0.56), about 0.580. This gives smooth feedback, avoids long products of tiny numbers, and makes confident mistakes expensive. This is why this probabilistic model uses binary cross-entropy, rather than an arbitrary right/wrong counter. It treats labels as supervised examples, not as independent facts about language.

      
Log means base e throughout. For the mathematical sigmoid, the score-based forms used in the code are:

      
Label 1: loss = log(1 + exp(-score))
Label 0: loss = log(1 + exp(score))

      
These express the feedback we established from the examples: raising the score shrinks the first cost and increases the second. They do not introduce another task.

A real neighbour need not receive 100%

      
The same pair can receive label 1 when observed and label 0 when drawn as noise in another example. Imagine a pair appearing four times as data and once as noise. A constant q = 0.8 gives those five labels more likelihood than q = 1, which assigns zero probability to the noise label. This is an illustrative count, not a claim about the selected pair.

      
Repeated conflicting examples therefore favour a statistical compromise. This explains both nonzero loss and why q is not simply the probability that a word is a real neighbour.

      
Numerical safeguards at extreme scores
The code evaluates log(1 + exp(value)) stably from the unclipped score. Its sigmoid helper clips scores to [-15, 15]. Displayed outputs and update gradients therefore approximate the mathematical sigmoid at extremes; the loss itself remains unclipped.

    

  


  

    
4. Connect the loss to changes in both vectors

    

      
A high loss does not identify which weight to change. A derivative measures local sensitivity: how a small change to one weight would affect loss while other weights stay fixed. Collecting those sensitivities for all weights gives the gradient.

      
Inspect the effect of changing just one weight

      
For the selected observed example, change only the first coordinate of its candidate output vector. Keep the input and all other weights fixed, and recalculate the same label-1 loss:

    

    

      
These probes illustrate sensitivity; they are not training updates
ProbeOutput weightObserved-example loss

    

    

      
If increasing the weight increases the loss, its gradient is positive and lowering it is locally helpful. If increasing it reduces the loss, its gradient is negative and raising it is locally helpful. The gradient is not the loss or an updated weight. The code computes it by differentiation, rather than trying many small probes.

      
Carry feedback backward through the calculation

      
At a score, the feedback is sigmoid(score) - label. An output of 0.6 on label 1 gives 0.6 - 1 = -0.4: increasing the score locally reduces loss. The same output on label 0 gives 0.6 - 0 = 0.6: decreasing the score locally reduces loss.

      
That tells us about the score, not yet about a coordinate. A score includes products of input and output coordinates. If an input coordinate is negative, lowering its paired output coordinate raises their product. The chain rule combines the loss's sensitivity to the score with the score's sensitivity to each coordinate.

      

      
Use the sign and choose a step size

      
Subtracting a small multiple of a gradient handles either sign. The learning rate sets that multiple. A local downhill direction does not promise improvement after a very large move.

      
new weight = old weight - learning rate × gradient

The input coordinate also changes: its gradient uses the output coordinate as its multiplier. Both gradients use the values before the update. Otherwise, the second update would be based on a different starting calculation.

    

    
Apply one observed update, then each noise update

    
The implementation updates the observed pair first, then re-reads the center vector and updates each noise pair immediately. It does not calculate all four gradients from one frozen center vector. A repeated noise draw is another update, not a duplicate to discard.

The forward pass calculated scores, outputs, and losses. The backward pass connected those losses to weights. Applying the updates changes what the next forward pass will output. Without that last operation, repeating the calculations would teach the model nothing.

  


  

    
5. Repeat the updates and interpret the loss curve

    

      
An epoch processes all 108 observed pairs in shuffled order, with three new noise samples for each pair. The curve sums the observed and noise losses for each pair, then averages those sums across the epoch. It does not average the four contributions individually.

      
Before useful training, scores are small and q is near 0.5. Each binary example costs about 0.693, so an observed pair plus three noise examples costs about 4 × 0.693 = 2.773. That explains the initial scale.

Some loss reduction can happen without distinguishing words

      
There are three noise labels for each observed label. A model that always outputs q = 0.25 matches that overall 1:3 ratio without learning which words fit together. Its per-pair loss would be -log(0.25) - 3 × log(0.75) = 2.249, already below 2.773.

      
That constant-output baseline is the ochre line. A falling loss alone does not prove useful context distinctions. Inspect the actual outputs too: does the model treat observed contexts differently from other candidates?

      
A plateau is evidence to interpret, not a certificate

      
As predictions settle into a compromise, gradients can shrink or competing updates can balance. The loss may flatten. But new noise draws can still cause fluctuations, and limited dimensions or step size can restrict improvement. The plotted losses are collected while weights change, not at one frozen model, and are not a test-set evaluation.

      
Set the learning rate to 0 in the update section and replay. The embeddings and outputs stay fixed, though noise sampling can still make the recorded loss wiggle. Neither a flat curve nor fluctuations alone tell us that the model learned useful structure.

      
Do not compare this loss's numerical scale directly with full softmax or with another value of K. They sum different training objectives or different numbers of contributions.

Cosine compares vector directions while discounting lengths. This uses E against E, unlike training, which scores E against W. Words with shared contexts can receive related updates, but the algorithm does not directly minimize distances between their input embeddings.

      
We can reuse the input table to compare usage patterns or provide numerical inputs to another model. Its coordinates have no fixed meanings, and lower loss on this tiny corpus does not establish human-like understanding or generalization to new text.

    

    
The connection: we constructed labels from data and sampling, defined which outputs agree with those labels, turned agreement into a smooth cost, and used that cost's gradients to adjust both vectors. The repeated classification task is how the embeddings get their training signal.
